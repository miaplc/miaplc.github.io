Performance

How fast is a PLC that costs a few euros?

No promises: timings measured on real boards, and from there the maths for two concrete plants, a hotel and an irrigated field. Where a number is an estimate, it says so.

measured0.79 µsone ladder network “contact → coil” on ESP32
measured0.92 ms1000 ladder networks, one full scan
measured5.4×faster on the P4 with machine code, on a large program
measured~1.1 msround trip of a signed µLink I/O module, ESP32 PLC
The virtual machine

How long it takes, function by function

The ladder program becomes bytecode, which the VM runs every scan. The P4 is a more powerful processor and can also turn the simple parts into machine code, which the CPU runs directly. Lower times = faster.

FunctionESP32-WROOMESP32-P4

Values without “≈”: measured on the board. With “≈”: estimated, the P4 1.5 to 2.2 times the ESP32 with the same VM. Machine code pays off on large programs; on a small program full of loops and jumps it's slower than the VM (168 µs vs 136 µs, measured): that's why on the P4 it's a choice, not a must.

Program size

How much program fits

All memory and space values on this page are those of the PLC board: the program, DBs and data live there. I/O modules don't hold the program and the PC is only used to write it. Work memory is the board's RAM where the bytecode runs; on the ESP32 it shares it with the network, and WiFi alone takes a lot.

ESP32 PLC board

  • work memory, WiFi + Ethernet11.4 KB
  • work memory, Ethernet only~39 KB
  • DB area8 KB
  • load memory (flash)256 KB

In practice: 11 KB is about 1000 simple ladder networks, already a real plant. 39 KB (the maximum on the ESP32) holds a program with more than 100 functions: the test with Main and 101 FCs takes 14.8 KB.

ESP32-P4 PLC board

  • work memory (with PSRAM)~7.6 MB
  • program code, at most8 MB
  • DB area2 MB

How big is 4 MB? A simple network takes about ten bytes; one from a real plant, with comparisons and boxes, 30–60 bytes. An automatic machine has a few hundred networks; a complete production line a few thousand. The test's 4.3 MB correspond to tens of thousands of networks: the size of a whole department, not of one machine. For a hand-written program the P4's memory never runs out: the limit becomes inputs and outputs.

In practice · 1

The hotel: how many rooms?

Each room: 10 buttons, 10 lights, climate with temperature probe, valve and fan. A “Room” function written once and called for every room; one 64-I/O µLink module in the floor cabinet serves 5 rooms.

How to read the three calculators: move the slider and see whether the PLC can cope. They are cautious estimates: for memory we count twice what is really needed, so the numbers are not optimistic.

ESP32

ESP32-P4

A blink lasts 100–400 ms: under 100 ms from button to light no guest notices anything. With 200 rooms the ESP32 is already at its I/O module limit, while the P4 uses a small part of its memory: the free space is for other things (alarms, history, recipes). A bigger hotel is usually split over several PLCs, one per floor or wing.

In practice · 2

Irrigation: how many hectares before RAM runs out?

Each hectare: 2 sectors with valve, watering time and soil-moisture threshold, plus one probe. Plus a fixed station: pumps, pressure, dosers, sludge treatment, mixers, chemical probes.

ESP32

ESP32-P4

A field is in no hurry: even a half-second scan is fine. Here the real limits are memory and I/O points, not speed. Analog probes are read with modules that have analog inputs, or with Modbus sensors.

In practice · 3

Baggage conveyors

Each conveyor: 4 photocells, motor, bag tracking (where every item is), jams and diverters. Here speed matters: at 2 m/s a bag travels 4 cm in 20 ms, so we want every conveyor refreshed at least every 20 ms. One 64-I/O µLink module serves 15 conveyors.

ESP32

ESP32-P4

A large airport doesn't use one PLC: the system is split into zones, each with its own PLC. An ESP32 handles a small zone, a P4 a whole zone with room to spare. These are estimates: a real baggage system must be engineered and tested on site.

TLS runs on the other core and slows down neither the cycle nor µLink: the limit is RAM. On 10 November, with a test HTTPS connection, the editor Online and a Download together, the ESP32 PLC went down to 18–20 KB free. (A restart seen in that test did not depend on TLS: it was a firmware bug between the panel and the Download, fixed in 0.3.96.) On the ESP32 without PSRAM, in RUN, about 72 KB are left: one HTTPS connection would leave 16–20, and the browser opens more than one. That is why boards without PSRAM use HTTP with login and signed requests (integrity, no encryption) and must stay on an isolated network; HTTPS is on the boards with PSRAM: already on the P4 panel, being prepared on the P4 PLC.

How we did the maths

For each example we imagined the program for one room, one hectare or one conveyor, as a technician would write it: one function written once and called many times. Then we counted what it is made of and multiplied by the number on the slider.

ExampleWhat the program doesTime per unit (ESP32)Memory per unit (already doubled)
One hotel room10 buttons switch 10 lights, the climate drives valve and fan from the temperature~29 µs~0.2 KB of program + 48 bytes of data
One irrigated hectaretwo sectors: opens the valve for the set time when the soil is dry~26 µs~0.2 KB of program + 112 bytes of data
One baggage conveyor4 photocells, motor, tracks where every bag is, jams and diverters~34 µs~0.1 KB of program + 128 bytes of data
  • Time: from the measurements in the table above (a simple network 0.79 µs, an addition 1.4 µs). We count the P4 1.5 times faster than the ESP32, the most cautious estimate; with machine code, on large programs, 5.4 times (measured).
  • Memory: the count made on the program has been doubled, to stay on the safe side. The function written once (1–2 KB) is counted separately.
  • I/O modules: a µLink module has 63 usable inputs and 63 outputs, so it serves 5 rooms or 15 conveyors. The PLC talks to the modules every 5 ms; with many modules the round gets longer (at most 60 % of the time busy).
  • Reaction: from button to light, at worst, two µLink rounds plus one program scan.
  • P4 beyond 15 modules: extended configuration, 🚧 in development (up to 1000 I/O boards).
The formulas used 
scan    = 0.13 ms + N × (networks × 0.79 + boxes × 1.4 + 0.3 + params × 0.25) µs ÷ speed
memory  = fixed code + N × bytes per unit      ≤ work memory
data    = fixed data + N × data bytes          ≤ DB area
period  = max(5 ms, modules × time per module ÷ 0.6)

The calculator is in the site file assets/js/prestazioni.js: all starting numbers are at the top, with their source.
